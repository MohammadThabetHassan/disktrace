# GUI-first workflow contract, version 1

DiskTrace is a **native desktop GUI application first**. The command-line interface remains available for optional repeatable evidence workflows, but a person recovering files should be able to complete the normal path without typing a command.

## First launch

The desktop application opens as **DiskTrace**, a guided local-first recovery workspace with a quiet casework hierarchy. The compact header presents the local-only and read-only-source guarantees as inline case context alongside the current workflow state and a Help reference, rather than as a dashboard of status chips. A three-step working rail states the decisions in order: select an image, scan and review results, then export to a separate folder. On first launch, the central start sheet owns the two visible primary choices—select a local recovery image or open a harmless synthetic guided demo—while the rail retains path entry and explains that later filter and destination controls are available by scrolling.

| Step | GUI action | Safety boundary |
|---|---|---|
| **1. Select an image** | Use the native image picker or enter a local image path. The workflow rail marks the selected-image state. | The application reads the selected source; it does not write to the image. |
| **2. Scan and review** | Start a background scan, use resettable filters, review evidence cards, select a result, and read its method, validation label, source metadata, explanation, and bounded preview. The selected preview is prepared locally in the background so result navigation remains responsive. | A candidate is not a completeness, ownership, path, safety, or legal-admissibility guarantee. |
| **3. Recover safely** | Choose a separate existing destination, activate the visually distinct selected-result recovery action, then review the selected evidence and destination in a native confirmation window. | Source identity is rechecked, destination policy runs before output creation, and successful export receives a receipt. Cancelling the review window creates no output. |

During a scan, the workflow rail identifies a **Read-only scan active** state and explicitly explains that a byte percentage is intentionally absent because DiskTrace has no separately tested scan-progress contract. **Stop scan** changes the workflow state to **Stopping scan** while the local worker acknowledges a cooperative cancellation signal; the guidance states only that acknowledgement occurs at an implemented cooperative checkpoint, not within a promised latency. Cancellation is checked during source identity and full-image buffering reads; a cancelled scan produces no new session or candidate catalogue, while any previous completed catalogue remains available. Discovery still operates on already-buffered bytes, so stopping can wait for an active discovery routine to return. If the worker had already completed, its result is deliberately discarded rather than applied. The application never writes to the source or retains partial scan results.

Candidate and evidence-detail panes use bounded adaptive widths rather than a fixed split, preserving practical space at the supported minimum desktop width and allowing richer evidence explanation on wider displays. The completed session is presented as a compact case strip with progressive case and export records, keeping the evidence list above generic metrics in the reading order. When no image, completed result, or filtered result is available, the result workspace states the next safe action directly. When a result is selected, the evidence-detail panel scrolls independently so its preview and export controls remain reachable. If no separate destination is selected, it explains the destination requirement and makes **Choose destination** the only primary action. If source identity is not verified, it explains that recovery remains blocked and does not offer an export action.

Synthetic fixtures are available behind an advanced disclosure. They are intended for learning and regression testing only; they are not presented as real evidence images.

## Recovery Mode and Evidence Mode

**Recovery Mode** is the normal user path: image selection, scan, results, safe preview, destination selection, and selected-file export. Controls use ordinary recovery wording and put the safe desktop workflow before saved sessions, fixtures, or automation details.

**Evidence Mode** remains available inside the same workspace rather than as a separate command-only interface. It presents recovery candidates as selectable evidence cards with method and validation badges. For a selected result, **At a glance** presents recovery method and validation first, followed by recovered byte length and source offset; the bounded preview follows, then **What this evidence establishes**, method notes, and the collapsed candidate record containing the long trace handle. The evidence-scope panel distinguishes metadata/allocation findings from structural-carving findings and restates that acceptance is limited to the documented bounded range and validation state. This order helps users distinguish what is known from the method’s limitations before they encounter a recovery action. Text candidates retain a short local UTF-8 excerpt. PNG, JPEG, GIF, PDF, ZIP/Open XML, standard AVI, and a deliberately narrow self-contained MP4/MOV subset can show limited local structure facts such as dimensions, trailers, RIFF lists, MP4-family box names, PDF version, or central-directory metadata. GIF summaries verify the supported block stream and trailer; AVI summaries require bounded standard RIFF `hdrl` and `movi` lists; MP4/MOV summaries require bounded `ftyp`, `moov`, and `mdat` boxes and intentionally reject fragmented media. These summaries do not render, open, decode, decompress, execute, validate playback or codecs, prove completeness, establish authenticity, or assess file safety. The compact session strip presents source-integrity state, candidate and export counts, progressive case records, and receipt provenance. Its **Recheck source** control compares the current source against the saved session identity without scanning, exporting, changing the image, or discarding the historical catalogue. When a session has exports, **Audit exports** compares the persisted receipt JSON and current output SHA-256/BLAKE3 values against the recorded receipt, then keeps verified, changed, unavailable, or inconsistent findings in a progressive audit record. **Save case brief** uses the native save dialog to create a local Markdown summary of the current source status, candidate inventory, and recorded export-audit observations. It contains no source-image or recovered-file payload bytes. The audit and case brief are read-only and do not establish ownership, authenticity, malware safety, legal admissibility, or recovery completeness. Evidence details explain the limitations of each method instead of implying that a result is complete merely because export succeeded.

## Preview and export limits

Text candidates can receive bounded excerpts. Supported binary candidates can receive bounded structure summaries; unsupported or malformed binary candidates remain metadata-only. After selection, the desktop may briefly show **Preparing bounded local preview** while it rechecks the full saved-source identity and then reads only that candidate’s exact local byte range in the background. Replacing the selection or resetting the workspace cooperatively stops a superseded preview during its bounded range read, and stale preview results are discarded. This work remains local and read-only: it does not render, open, execute, or export the recovered file. New preview bytes are withheld when the saved source is changed or unavailable, including a same-length substitution discovered after the status strip was last refreshed; the historical candidate metadata remains visible and the user is directed to recheck or rescan. A current preview-worker failure is shown as **Bounded local preview unavailable**, not as an unsupported format. The application does not open recovered files automatically after export. A user must make a separate decision to inspect a recovered file in an appropriate environment.

After a quick or full format, filesystem metadata can be removed while some raw bytes remain recoverable. DiskTrace can search those bytes with supported metadata and structural-carving methods, but it cannot guarantee recovery of every former file, name, folder, fragment, encrypted item, overwritten sector, or SSD block that has been discarded through TRIM or later controller activity. The workflow always reads the source and writes recovered output only to a separate destination.

Saved sessions are an Evidence Mode aid, not a replacement for source identity. When a source image is changed or unavailable, the historical catalogue remains visible but recovery is blocked.

## Keyboard commands

The header exposes a **Help · F1** reference. The application supports `Cmd/Ctrl + O` to choose an image, `Cmd/Ctrl + Enter` to start a read-only scan, `Cmd/Ctrl + S` to save the current session, and `Up`/`Down` to compare the currently filtered recovery results. `F1` opens the reference and `Escape` dismisses it. `Cmd` means Command on macOS and Control on Windows or Linux. Commands that alter application state do not run while a text editor has focus, and each has a visible native-control equivalent.

## Accessibility and future validation

The native controls are keyboard-focusable through the GUI toolkit, filtered results can be reviewed with the arrow keys, and the expanded workflow rail scrolls independently to retain access to destination controls on shorter desktop viewports. This workspace has not yet completed a platform-native accessibility audit or screen-reader validation. Windows and Linux distribution scripts make the desktop workspace the default entry point; native launch, installation, accessibility, and update behavior still require validation on each supported platform before public release.
