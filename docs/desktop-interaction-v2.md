# Desktop Interaction v2 Contract

DiskTrace uses native file and folder selection only to populate local paths. The selected image is not opened by the picker and no data is uploaded. The picker filters for common image extensions as a convenience, but the recovery core remains responsible for inspecting the actual file and rejecting unsupported content.

A destination picker selects an existing local directory. Selection alone is not approval: the existing destination policy still runs during recovery and rejects source-image storage, nested source paths, symlink-equivalent source locations, and missing folders. The user sees a precise reason when a destination is refused.

Scanning runs in a background worker. The interface remains responsive and shows `Scanning locally` while the worker is active. Selecting **Stop scan** first changes the interface to `Stopping local scan` and disables duplicate stop requests. This is an honest intermediate state: the worker has received a cooperative cancellation signal but has not necessarily observed it yet.

The first cancellation stage checks the signal before source inspection, before and between 1 MiB source-hash reads, and before and between 1 MiB full-image buffering reads. A cancellation observed at those points produces no session or candidate catalogue. The previous completed catalogue, if any, stays available. The desktop shows `Scan stopped` only after the worker reports that cancellation was acknowledged.

Current discovery still parses an already-buffered byte slice. It checks cancellation before and after discovery but cannot interrupt an individual filesystem or signature parser yet. This implementation does not terminate an operating-system thread, make unsafe I/O interruption claims, or retain partial scan results. If a background scan has already completed when the user requests a stop, its completed result is deliberately not applied and the interface reports `Scan result discarded` instead.

Selected previews run in a separate generation-stamped background worker. Replacing a selection, resetting the workspace, or rebuilding the catalogue signals cooperative cancellation for any superseded preview during its bounded local range read; stale results are not applied. Before it reads that range, the worker rechecks the completed session’s full source identity on one local file handle. It then reads only the selected candidate’s exact validated byte range in 1 MiB chunks. Once those bounded bytes exist, their format-aware extraction remains subject to the current non-interruptible extraction boundary. A selected preview is prepared only while the saved session source is verified. If the source is changed or unavailable, or if it changes after the UI status was cached, the historical candidate metadata remains visible but no new preview bytes are read. A current worker failure is shown as `Bounded local preview unavailable`, distinct from the normal metadata-only state for a format without an available bounded summary.

The UI uses distinct recovery-state messages for `Ready`, `Scanning image`, `Stopping scan`, `Scan stopped`, `Scan complete`, and `Recovery export completed` or `not completed`. Status messages name the next safe action and retain the existing rule that no result is a guarantee of recovery.
